# Telco Customer Churn Prediction

基于 Python 与 Scikit-learn 的电信客户流失预测项目。通过数据审计、特征预处理、基线模型对比、随机森林参数调优和分类阈值选择，构建可复现的客户流失预测流程，并支持对单个客户进行预测。

## 1. 项目简介

客户流失会影响企业的客户留存和长期收入。本项目使用电信客户数据，预测客户是否可能流失，并分析模型识别流失客户时的表现。

项目重点不只是训练一个分类器，而是完整实践机器学习建模流程：

- 数据质量审计与异常值处理
- 训练集、验证集和测试集划分
- 数值特征与类别特征的差异化预处理
- 逻辑回归基线与随机森林模型对比
- 基于验证集的超参数搜索与分类阈值选择
- 基于置换重要性的特征分析
- 模型持久化与单客户预测

## 2. 项目目标

将客户流失预测建模为二分类问题：

- `Churn = Yes`：客户流失，标签为 1
- `Churn = No`：客户未流失，标签为 0

本项目重点关注 Recall、Precision、F1 和 ROC-AUC。

其中，Recall 衡量模型识别实际流失客户的能力；Precision 衡量模型预测为流失的客户中，实际流失客户所占的比例；F1 综合考虑 Precision 和 Recall；ROC-AUC 衡量模型区分正负类别的能力。

## 3. 数据说明

数据文件：`WA_Fn-UseC_-Telco-Customer-Churn.csv`

数据包含客户基本信息、使用服务情况、合同类型、付款方式、在网时长、费用及流失标签等字段。

| 数据项目 | 结果 |
|---|---:|
| 原始样本数 | 7,043 |
| 原始字段数 | 21 |
| 实际流失率 | 26.54% |
| 重复记录 | 0 |
| `TotalCharges` 空白记录 | 11 |

数据审计发现，11 条 `TotalCharges` 空白记录均对应 `tenure = 0` 且 `Churn = No`。本项目将该字段转换为数值类型，并将这些空白值填充为 0，以完成后续建模。

建模前删除 `customerID`，避免将客户标识符作为预测特征；目标变量 `Churn` 单独提取，不参与特征输入。

## 5. 建模流程

### 5.1 数据划分

采用分层抽样，并固定随机种子 `random_state=42`。

| 数据集 | 样本数 | 用途 |
|---|---:|---|
| 训练集 | 4,225 | 拟合模型 |
| 验证集 | 1,409 | 参数选择、阈值选择 |
| 测试集 | 1,409 | 最终留出评估 |

测试集不用于超参数搜索或分类阈值调优，以尽量减少模型选择过程对最终评估的影响。

### 5.2 特征预处理

使用 Scikit-learn Pipeline 和 ColumnTransformer 组织预处理流程。

**数值特征：**
- `SeniorCitizen`
- `tenure`
- `MonthlyCharges`
- `TotalCharges`

处理方式：中位数填补、标准化。

**类别特征：**

其余 15 个类别特征采用众数填补与 One-Hot 编码，并通过 `handle_unknown="ignore"` 处理预测阶段可能出现的未知类别。

将预处理和分类器组合到同一个 Pipeline 中，确保训练与预测时使用一致的处理逻辑。

### 5.3 基线模型

首先训练逻辑回归模型，作为可解释、易于建立的基线。

验证集在默认分类阈值 0.5 下的结果：

| 指标 | 逻辑回归 |
|---|---:|
| Accuracy | 0.8027 |
| Precision | 0.6579 |
| Recall | 0.5348 |
| F1 | 0.5900 |
| ROC-AUC | 0.8360 |

该结果为验证集上的基线表现，不是最终测试集结果。

### 5.4 随机森林与参数调优

使用随机森林探索不同树深度和叶节点最小样本数的组合，并在验证集上以 F1 作为主要选择依据。

选定的参数：

- `n_estimators = 200`
- `max_depth = 8`
- `min_samples_leaf = 2`
- `class_weight = "balanced"`
- `random_state = 42`

其中，`class_weight="balanced"` 用于缓解类别不平衡带来的训练偏向。

### 5.5 分类阈值选择

二分类预测通常以 0.5 作为默认阈值，但不同阈值会影响 Precision 与 Recall 的平衡。

本项目在验证集上搜索 0.20 至 0.80 的候选阈值，最终选择：

`threshold = 0.52`

该阈值在已测试的候选值中取得最高验证集 F1。最终预测时，当流失概率不低于 0.52 时，输出“可能流失”；否则输出“可能不流失”。

阈值是根据本项目验证集和当前目标选择的，不代表它在所有业务场景中都是最优值。

## 6. 最终测试集结果

选定随机森林参数和分类阈值后，在留出的测试集上进行最终评估。

| 指标 | 测试集结果 |
|---|---:|
| Accuracy | 0.7608 |
| Precision | 0.5356 |
| Recall | 0.7433 |
| F1 | 0.6226 |
| ROC-AUC | 0.8417 |

测试集混淆矩阵：

|  | 预测未流失 | 预测流失 |
|---|---:|---:|
| 实际未流失 | 794 | 241 |
| 实际流失 | 96 | 278 |

**结果解读：**

- Recall 为 0.7433，模型识别出了约 74.33% 的实际流失客户。
- Precision 为 0.5356，模型预测为流失的客户中，约 53.56% 实际流失。
- ROC-AUC 为 0.8417，说明模型具有一定的正负类别区分能力。
- 在当前阈值下，模型仍存在误报：241 名实际未流失客户被预测为流失。

对于客户留存业务，漏掉一个潜在流失客户和误报一个正常客户的业务成本可能不同。因此，实际应用时应结合触达成本、挽留成功率和客户价值，进一步选择适合业务目标的阈值。

以上为当前实验记录，不应在查看测试集结果后继续针对测试集反复调参。

## 7. 特征重要性分析

采用验证集上的置换重要性（Permutation Importance），以 ROC-AUC 为评分指标，重复置换 5 次，评估打乱单个特征后模型表现的变化。

当前排名靠前的特征如下：

| 特征 | 置换重要性均值 |
|---|---:|
| Contract | 0.068643 |
| InternetService | 0.027587 |
| tenure | 0.019041 |
| OnlineSecurity | 0.008903 |
| TotalCharges | 0.008513 |
| TechSupport | 0.005992 |

`Contract` 在本次分析中具有最高的置换重要性，其次是 `InternetService` 和 `tenure`。

需要注意，置换重要性反映的是特征对当前模型预测表现的贡献，不代表因果关系。对于相互关联的特征，重要性也可能受到相关性和数据分布的影响。

完整结果保存在 `reports/feature_importance.csv`。

## 9. 如何运行

### 9.1 环境准备

建议使用 Python 3.11，并在项目根目录打开终端。

创建虚拟环境的示例：

```bash
python -m venv .venv
```

Windows 激活环境：

```bash
.venv\Scripts\activate
```

安装依赖：

```bash
pip install -r requirements.txt
```

### 9.2 数据审计

```bash
python "src/Python File/data_audit.py"
```

### 9.3 训练模型

```bash
python "src/Python File/train.py"
```

训练完成后，模型与评估结果应保存至 `models/` 和 `reports/` 目录。

### 9.4 单客户预测

确保模型已经训练并保存，再运行：

```bash
python "src/Python File/predict.py"
```

示例输出：

```text
========== 客户流失预测 ==========
预测流失概率：37.78%
分类阈值：0.52
预测结果：可能不流失
```

上述输出对应脚本中的示例客户。更换客户特征后，预测概率和分类结果可能发生变化。
